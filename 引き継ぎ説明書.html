1. このシステムの全体像

一言で言うと

タブレットやPCのブラウザで動くレジアプリ。売上データはGoogleスプレッドシートに自動で記録される。

3つのアプリ

アプリ役割URL
POS main本番のレジ（実際に使う）https://kuchunomura.github.io/pos-main
POS test予備・確認用のレジ（mainが不具合の時に使う）https://kuchunomura.github.io/pos-app-test
yoyaku予約管理（別アプリ・別管理）https://kuchunomura.github.io/yoyaku

データの保存先（スプレッドシート）

アプリが記録するデータは、3つのGoogleスプレッドシートに入っています（すべて職場のGoogleアカウント内）。

※ 具体的なURL（アドレス）は毎月変わるものがあるため、ここには載せていません。今のURLは各アプリの「設定」や、各GASの中で確認します。

2. 使う「道具」の説明

改修作業で使う道具は4つ。それぞれ別のものです。①の中に②③がある。

道具① VS Code（青い三角アイコンのアプリ）

ファイルを開いて編集するためのソフト。 HTMLやJavaScriptのファイルを開く「作業台」。VS Code自体に改修能力はなく、「開く・見る・編集する」だけ。

道具② Claude Code（VS Codeの中にあるオレンジ枠のチャット）拡張機能で①に入れている

AIにファイルの改修を依頼するチャット。 日本語で「○○を追加して」と頼むと、AIがファイルを自動で書き換える。Claude Code が「頭脳」、VS Code が「作業台」。

道具③ ターミナル（チャット下にある白い画面　通常は非表示）

文字でコンピューターに命令する画面。 GitHubへのアップロード（gitコマンド）などに使う。普段はClaude Code が代わりに操作するので自分で打つことはほぼない。

道具④ GitHub（インターネット上のファイル置き場）

ファイルを保存・公開するクラウドサービス。 このプロジェクトでは、ファイルの保存場所であり、タブレットがアクセスするURL（GitHub Pages）でもある。

このプロジェクトのファイルは GitHub が本物（原本）。手元のPCはただの作業コピー。PCが壊れても GitHub から作り直せる（→第12章）。

4. ファイルの場所と役割

置き場所（重要）

このシステムのファイル一式は、作業する各パソコンの中（それぞれのCドライブ）の C:\dev\pos-yoyaku というフォルダーにあります。
インターネット上でも Google ドライブでもなく、パソコンに置いた普通のフォルダーです。
1台だけにある物ではなく、GitHub経由で各PCに同じものを同期しています（現在は自宅PCと、空中の村の大PC・小PCに入れてあります）。

開き方

  • VS Code：メニュー「ファイル → フォルダーを開く」で C:\dev\pos-yoyaku を選ぶ。
  • Windowsのエクスプローラー（フォルダーの窓）：上のアドレス欄に C:\dev\pos-yoyaku を貼って Enter。
  • どのパソコンでも同じパス C:\dev\pos-yoyaku で開きます（中身はGitHubでそろえているため／→第12章）。

### ⚠ 絶対に守ること：Google ドライブに入れない
このフォルダを Google ドライブ / OneDrive の同期フォルダの中に置かないこと。
2026/09 に Google ドライブ デスクトップが全リポジトリの履歴（.git）とメモリを破壊した事故があり、C:\dev（＝同期対象外の場所）へ移しました。
- Google ドライブ デスクトップは基本オフのまま。起動したまま C:\dev を触らない。
- 2台のPCで共有したいときも Google ドライブは使わず、GitHub 経由にする（→第12章）。

5. アプリのデータの流れ

データの保存場所は2か所

【端末内】 localStorage … そのブラウザの中に保存
  ・商品リスト／カテゴリー設定／売上履歴／保留／各種設定
  ※ インターネット不要で動く／ブラウザのデータを消すと消える！

【Google】 スプレッドシート … GAS経由でインターネットに保存
  ・売上データ（日付別シート）
  ※ ブラウザのデータを消しても残る

決済したときの流れ

商品タップ → カート（端末内） → 支払ボタン
  → localStorage に保存 ＋ 同時にGASへ送信 → スプレッドシートに1行追加

複数台で使うとき

レジ1 →┐
        ├→ GAS → スプレッドシート（全台合算）
レジ2 →┘
※ 端末どうしは直接つながらない。スプレッドシートが全員の集計場所。

6. 改修の基本手順

Step 1: Claude Code に依頼「レジに○○を追加して」（どのアプリか＝レジ／予約を伝える）
Step 2: Claude がファイルを書き換える（レジは main と test の両方に同じ変更／まだPC内だけ）
Step 3: 「GitHubにアップロードして」と頼む（デプロイ＝main・test両方）
Step 4: 数分待って本番URLを再読み込みし、反映を確認

2台のPCで作業する場合は、作業を始める前に「最新を取り込んで（git pull）」と頼むこと。もう片方のPCでの変更を取り込んでから作業する（→第12章）。

Claude Code への良い頼み方

  • どのアプリか（レジ／予約）
  • 何を（追加・削除・変更・デザイン）
  • 具体的に（商品名・金額・色など）

悪い例：「コーヒー追加して」（ファイル？金額？カテゴリ？不足）／「全部直して」（内容不明）

7. 「main」と「test（予備）」の関係

レジには main（本番） と test（予備） の2つがあります。

  • main …/pos-main … 実際に使う本番レジ。改修はこちらが基準。
  • test …/pos-app-test … 普段は使わない予備レジ（本番が不調なときの代わりに使える）。
  • データは main と同じスプレッドシートに同期する＝test で会計しても売上は本番と同じ場所にたまる。
  • そのため main を改修したら test にも同じ変更を入れて、中身（バージョン）を揃えておく（Claude が両方へ同時に適用します）。
  • ※以前は「まず test で試してから main へ」という使い方でしたが、今は test ＝予備という位置づけに変わりました。

8. デプロイとは何か

PC内で編集したファイルを、インターネット（GitHub）に公開すること。

編集しただけではPCの中にしかなく、タブレットには反映されません。GitHubにアップロードして初めて反映されます。

git add    … このファイルをアップロード対象にする
git commit … 変更に名前をつけて記録する
git push   … GitHubにアップロードする
※ この3つをまとめて「デプロイ」。Claude Code が全部やってくれる。

バージョン番号のルール（重要）

index.html を変更したら、バージョン番号を必ず1つ増やす決まり（どんな小さな修正でも）。これで「今タブレットに出ているのが最新か」を見分けられる。

変更のたびにセットで更新する3つ（Claudeが自動でやる）:
  ・APP_VERSION     → +1
  ・APP_BUILD_DATE  → 更新日時に
  ・CLAUDE.md の「現在のバージョン」 → 同じ番号・日付に

番号を上げ忘れると、タブレットが「新版が出た」と気づけず古いままになる。

デプロイ後に反映が遅くても、追加のアップロードを連打しないこと。 進行中の公開処理を失敗させる。1回push したら数分待つ。

9. GAS（Google Apps Script）の改修　スプレッドシートの内容を改修する時にコードを張り替えることが多い。

この改修が慣れるまでは一番ややこしい。Claudeに聞きながらやれば、たいていの場合は出来る。

GASとは

Googleのサーバーで動く拡張機能のプログラム。レジから送られた売上をスプレッドシートに書き込む「翻訳係」。

変更が必要なケース

  • スプレッドシートの列を追加・変更／集計の計算を変える／新しいデータ項目を記録する

改修手順

  1. gas_script.js を Claude Code で編集（PC内のファイル）
  2. ブラウザで script.google.com（Apps Script）を開く
  3. 対象プロジェクトのコードを全選択して削除 → 編集した内容を貼り付け → 保存（Ctrl+S）
  4. 「デプロイ」→「デプロイを管理」→ 鉛筆 → 「新しいバージョン」→ デプロイ

保存だけでは反映されません。 ウェブアプリ（レジが通信する側）のGASは、必ず「新しいバージョン」で再デプロイして初めて反映される。どの gas_script.js を貼るかは Claude がフルパスで示すので、その通りに。

GASのURL（住所）は再デプロイしても変わりません。 だからレジ側の設定を変える必要はない（月初のSS切替も、URLは不変＝第10章）。

初回だけ出る警告（安全・進めてOK）

GAS（onOpen・集計・月切替など）を初めて実行して認可を求められると、こう出ます：

このアプリは Google で確認されていません
アプリが、Googleアカウントのプライベートな情報へのアクセスを求めています。デベロッパー（staff.kuchunomura@gmail.com）と Google によって確認されるまで…

進め方：

  1. 左下の 「詳細」（または「詳細設定」）をクリック
  2. 一番下の 「（プロジェクト名）（安全ではないページ）に移動」 をクリック
  3. 内容を確認して 「許可」 をクリック

→ これは自分たち（staff.kuchunomura@gmail.com）が作ったスクリプトを自分で使うときの通常表示。外部アプリではないので許可して問題なし。以降そのスクリプトでは出ない（別の新しいSS＝別スクリプトでは再度出る）。

index.html と GAS の連携

index.html（レジ） → GAS WebアプリURL → gas_script.js → スプレッドシート
GAS WebアプリURL は、設定タブ →スプレッドシート連携 に入っている。

10. 毎月やること（定期メンテナンス）

毎月はじめに、売上の記録先を「その月のスプレッドシート」に切り替えます。POS（本番売上）と手動集計（報告書用）の2つがあります。

A. POS main を新しい月のSSに切り替える

その月の最初の売上を打つ前に行う（前月分が前月SSに残るように）。

  1. 新しい月の空スプレッドシートを用意する
  • Claude に「来月のPOS mainのSSを作って」と頼むとGASの createNextMonthSS() を実行して作れる（空でOK＝売上受信時に日別シートが自動生成される）。会社アカウントで作ること。
  • タイトルの慣習は 「○月POS main」（test系は「○月POS test」）。
  1. pos main のレジアプリを開く → 「📂 月初シート切替」 を押す
  2. 「📊 同期先シート（GAS）」欄に新SSのURL（IDだけでも可）を貼る → 「切り替える」 → 「同期先 ✅」で完了
  3. 「📋 手動集計シート」欄は空欄でOK

ポイント：

  • pos test は何もしなくてよい（同じSSへ受け身で同期する予備レジ）。
  • GASのURL・再デプロイは不要。切り替わるのは書き込み先SSだけ。
  • 切替は必ずその月最初の売上の前に。

B. 手動集計SS（報告書用）の新しい月を作る

このスプレッドシートはトラブル時に売上データを守るため、あえてレジから同期せず手動で1日ごとにmainからコピペしている。
面倒ならmainに集計機能をつけて完結させるようにClaudeCodeに行って改修可能。
手動集計はPOS同期SSとは別物で、毎月まるごと別ファイルにします。コピーの自動化はGoogle仕様でできない（ボタンではコードが複製されない）ので、手動コピーが必須。

  1. 今使っている手動集計SS（前月分）をブラウザで開く
  2. 「ファイル」→「コピーを作成」（←コード付きで複製できる唯一の方法）
  3. できたコピーを開く
  4. メニュー 「📅 集計」→「🔄 新しい月に切り替え」 → 新しい月を選択
  • → 日別タブが新月に作り替わり、ファイル名も変わる（最新日付が左）
  1. 元ファイルはそのまま残す＝その月のアーカイブ（後からでも再集計できる）
  • 初回の「🔄切り替え」実行で第9章の「確認されていません」警告が出る → 同じ手順で許可。
  • 迷ったらSS内の 「📖 使い方・月替わり手順」シートに手順が常設されている。
  • 日別タブが古い順になったら「↔️ 日別タブを最新順に並べ替え」。

12. 別のPCで作業する・環境を作り直す

別のPC（職場PCなど）で作業したいとき、またはPCが壊れて作り直すときの手順。Google ドライブは使わず、GitHub から取り寄せます。

詳しい手順は C:\dev\pos-yoyaku\SETUP_2PC.md にあります。要点だけ：

仕組み：GitHubを“真ん中”にして同期する

ファイルの原本は GitHub。各PCはその作業コピーを持ち、GitHub経由で中身をそろえます。
自動では揃いません。上げる(push)／降ろす(pull) で行き来させます。

           どれかのPCで編集
               │  push（上げる）
               ▼
       ┌───────────────────┐
       │      GitHub        │  ← 真ん中・原本
       └───────────────────┘
               │  pull（降ろす）
               ▼
     ほかのPC（自宅／空中の村 大・小）で最新になる
  • push しただけでは、他のPCには自動で届きません。 他のPCが pull して初めて最新になります。
  • 鉄則：作業の前に pull、作業の後に push。これを守れば、どのPCで編集しても全PCが同じ状態に揃います。
  • この pull / push は Claude Code がやります。「最新にして」（pull）／「上げといて」（push）と頼むだけ。改修を頼めば最後の push まで自動でやります。コマンドを覚える必要はありません。

初回だけ（新しいPCで）ブラウザでClaudeに聞きながらやればOK

  1. Git・Node.js・VS Code・Claude Code 拡張 を入れる
  2. GitHubにログイン（会社 kuchunomura、または承認済みの個人アカウント）
  3. 3つのアプリを GitHub から clone（フォルダ名を厳密に合わせる）：

```
C:\dev\pos-yoyaku\pos reji\pos main ← kuchunomura/pos-main
C:\dev\pos-yoyaku\pos reji\pos test ← kuchunomura/pos-app-test
C:\dev\pos-yoyaku\yoyaku ← kuchunomura/yoyaku
```
→ これだけで、そのPCでも編集・push・自動デプロイができる。

  1. CLAUDE.md・手動集計GAS・メモリも揃えたい場合は、SETUP_2PC.md の「第4のリポ（meta）」手順に従う。

毎回（両Pc共通） ←これはClaudeCodeの仕事。

  • 作業前に「git pull」で最新を取り込む／作業後に push して帰る（押し忘れると、もう片方のPCに最新が来ない）。
  • どちらのPCも同じパス C:\dev\pos-yoyaku で開く。

困ったら GitHub が原本。ローカルがおかしくなったら、壊れたフォルダを消して clone し直すのが最速。

13. 予約アプリ（yoyaku）の構造・改修・トラブル

POSレジとは別アプリの予約管理アプリです。
考え方（Claude Codeで改修→GitHubにデプロイ→URLで使う）はレジと同じですが、いくつか違いがあります。

📘 使い方（スタッフ向け）は別冊「予約アプリ（yoyaku）取扱説明書」にあります：https://kuchunomura.github.io/yoyaku/予約アプリ%20取扱説明書.html（原本 yoyaku/manual.md）。この章は構造・改修・トラブルの説明です。

13-1. 予約アプリとは（全体像）

  • URL：https://kuchunomura.github.io/yoyaku（本番1本。レジのような test版/main版の分割はありません）
  • 画面のタブ：一覧（予約リスト）／カレンダー（予約メモ付き月表示）／追加（手入力で予約を足す）／設定
  • データの出どころはWordPressの予約フォーム。そこからCSVを書き出してアプリに取り込みます。

13-2. データの流れ（レジと違う所）

① お客様がホームページの予約フォーム（WordPress）で予約
② 管理画面から予約一覧の CSV をダウンロード
③ 予約アプリで「📥 取込orドラッグ」→ CSVを読み込む（端末内に反映）
④ 端末内の予約は GAS 経由で「予約スプレッドシート（yoyaku SS）」に同期
⑤ 複数端末は、スプレッドシートを介してお互いの変更を同期（3方向マージ）
→ここはトラブりやすいので常に同期内容が正しいかを確認しておく。かなり直したが完璧ではない。
  • CSV取込のクセ：WordPressのCSVの日時は世界時刻(UTC)で出るので、日帰りの開始時刻はアプリ側で+9時間して日本時間に直しています。
  • 複数端末の同期：2台以上で同時に使っても、片方の編集がもう片方に消されないよう「3方向マージ（元の状態・自分の変更・相手の変更をつき合わせる）」で安全に合流します。表示中は10秒ごと＋画面復帰/タッチで即同期。

13-3. ファイルの場所

C:\dev\pos-yoyaku\yoyaku\
├── index.html        ← 予約アプリ本体（これ1つで全部入り）
├── gas_script.js     ← 予約SS側のGAS（同期の受け口）
└── CLAUDE.md         ← 予約アプリ用の技術メモ
  • GitHub リポジトリ：kuchunomura/yoyaku。
  • バージョン番号は APP_VERSION（index.html内）直読みで、レジのような version.json はありません（番号を上げれば各端末が自動更新に気づく）。

13-4. 改修の注意（レジとの違い）

  • test版が無い＝1本勝負。壊すと本番に直で響くので、変更は小さく・確認しながら。心配なら「まず一部だけ」「動作確認してから次」とClaudeに頼む。
  • 改修の頼み方・デプロイ（GitHubにアップロード）・バージョン番号を上げる決まりはレジと同じ。
  • 予約SS側のGAS（yoyaku\gas_script.js）を変えたら、レジと同様に「新しいバージョンで再デプロイ」が必要（保存だけでは反映されない）。同期の挙動を変えた時は特に注意。

13-5. 予約アプリでよくあるトラブル

  • 他の端末に反映が遅い／変更が元に戻る：同期の仕組み上まれに起きる既知の課題。表示している端末は同期し続ける作りだが、裏に回した端末は止まる。画面を表に出す（タッチする）と即同期する。繰り返す時はClaudeに「同期が戻る」と伝える。
  • 取り込んだ予約が消えた／取りこぼす：取込直後に別端末の同期が割り込むと起きることがあった（対策済み）。取込直後は少し待って、一覧に出そろったか確認。
  • チェックアウト等のチェックが消える：複数端末で別々の項目を編集するとぶつかることがあった（項目単位のマージで対策済み）。消えたらClaudeに状況を伝える。
  • キャンセルした予約が復活する：CSVに無い予約の扱い・同期の合流で起きうる。取込の取り消しで戻せる。
  • いずれもデータの最終保管は予約スプレッドシート。おかしくなったらまずSSの中身と版履歴を確認。

→基本Claudecodeに聞く。

13-6. もっと詳しい技術メモ

予約アプリの細かい仕様・過去の不具合と対策は、**メモリ（_claude_memory）の yoyaku-* 各ファイル**に記録してあります（同期・CSV取込・レンタルメモ・年間パス等）。改修時はClaudeがそこを見て判断します。

15. 困ったときのチェックリスト

アプリが動かない・エラーが出る

  • [ ] Claude Code に「エラーが出ています」＋画面の文言を伝える
  • [ ] 「1つ前のバージョンに戻して」と頼む（Gitの履歴から戻せる）

スプレッドシートに売上が書き込まれない

  • [ ] 設定タブ →スプレッドシート連携 →「接続テスト」でOKが出るか
  • [ ] GAS WebアプリURLが正しく入っているか
  • [ ] 売上タブ →「同期」→「今日分」で手動送信を試す

改修後にアプリが古いままに見える

  • [ ] GitHubにアップロード（デプロイ）したか
  • [ ] バージョン番号が新しくなったか／ブラウザのキャッシュをクリアしたか
  • [ ] デプロイ直後なら数分待つ（反映待ち。連打しない）

誤った改修でデータが消えた・壊れた

  • [ ] 「1つ前に戻して」でGitから復元
  • [ ] 端末内（localStorage）が消えた → エクスポートしたJSONからインポートで復元
  • [ ] スプレッドシートのデータは消えない

2台のPCで食い違う / PCが壊れた

  • [ ] 作業前の「git pull」を忘れていないか
  • [ ] どうしても直らない → フォルダを消して GitHub から clone し直す（第12章）

⚠ Google ドライブ デスクトップが起動していないか（最重要）

  • [ ] C:\dev\pos-yoyaku が Google ドライブ/OneDrive の同期対象に入っていないか。入れない・起動しない（第4章）
